# критические риски
## R01 Разработчик не успеет выполнить задачу в срок
- почему она опаснее остальных: задержка на любом этапе замедляет все последующие задачи
- какие задачи проекта она может затронуть: интеграция, сборка, тестирование
- какие последствия возникнут, если ничего не предпринимать: срыв срока сдачи, сокращение или полное исключение тестирования, падение качества
## R06 Нехватка времени на тестирование
- почему она опаснее остальных: тестирование стоит в конце цепочки и накапливает все предыдущие задержки
- какие задачи проекта она может затронуть: исправление дефектов, подготовку финальной сборки и демонстрации
- какие последствия возникнут, если ничего не предпринимать: заказчику передадут продукт с необнаруженными ошибками, потребуются доработки после сдачи, возможен отказ и потеря доверия
## R03 Внешний API окажется недоступен в критический момент
- почему она опаснее остальных: команда не контролирует внешнюю сторону и не может починить её сама
- какие задачи проекта она может затронуть: интеграцию с внешним сервисом, демонстрацию работающей системы, приём проекта
- какие последствия возникнут, если ничего не предпринимать: заказчик не увидит работающий результат и не примет проект
